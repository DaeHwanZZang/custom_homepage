# Custom Homepage

[English](README.md) · **한국어**

서버도, 빌드 과정도, 외부 의존성도 없는 **단일 파일 오프라인 우선** 브라우저 시작 페이지입니다. `index.html`을 로컬에서 열어 Safari(또는 Chrome)의 홈페이지/새 탭 페이지로 지정해 사용합니다.

Anthropic Claude 스타일을 따랐습니다: 아이보리/차콜 배경, 코랄 포인트 컬러, 세리프 디스플레이 글꼴.

## 기능

- **바로가기 그리드** — 자주 쓰는 사이트로 한 번에 이동하는 타일. 실제 사이트 파비콘을 표시하며, 아이콘이 없으면 이니셜 색상 타일로 대체됩니다.
  - **Edit**를 누르면 편집 모드로 진입: 타일을 드래그해 순서 변경, 타일 클릭으로 이름/주소 수정, **×**로 삭제.
  - 점선 **+** 타일을 눌러 새 바로가기 추가.
- **검색창** — 페이지 로드 시 자동 포커스. 검색어를 입력하면 Google 검색, URL/도메인을 입력하면 바로 이동합니다. 입력 중 자동완성 제안이 실시간으로 표시됩니다(Google Suggest 이용).
- **히스토리 페이지** (`history.html`) — 이 페이지에서 클릭한 바로가기와 직접 입력해 이동한 주소를 간단히 기록합니다(일반 검색어는 프라이버시를 위해 **기록하지 않음**). 항목을 클릭하면 다시 방문하고, 버튼 하나로 전체 기록을 지울 수 있습니다.
- **할 일(To-dos)** — 가벼운 체크리스트. 작업 추가, 완료 체크, 완료 항목 정리. 로컬에 저장됩니다.
- **시계·날짜·인사말** — 실시간 갱신되며, 시간대에 따라 인사말이 바뀝니다.
- **다크/라이트 모드** — 기본은 시스템 설정을 따르고, 모서리 버튼으로 수동 전환도 가능합니다(선택 사항 저장됨).
- **Google 앱 메뉴** — 우측 상단 점 아이콘을 누르면 Gmail, Drive, Calendar, Docs, YouTube 등으로 가는 바로가기가 공식 Google 아이콘과 함께 표시됩니다.
- **AI 바로가기** — 좌측 상단에 Gemini / ChatGPT / Claude 아이콘 고정.
- **기기 간 동기화(Sync)** — 비공개 GitHub Gist를 이용해 바로가기·할 일·테마를 여러 기기 간에 동기화할 수 있습니다(아래 [기기 간 동기화](#기기-간-동기화) 참고).
- **모바일 대응** — 휴대폰 화면에 맞게 조정되는 반응형 레이아웃(모서리 버튼이 상단 한 줄로 접히고, 탭 영역 확대, iOS 포커스 시 자동 확대 방지).

사용자가 설정한 모든 것(바로가기, 할 일, 테마, 히스토리)은 브라우저의 `localStorage`에 저장됩니다. Sync를 직접 켜지 않는 한 어떤 데이터도 기기 밖으로 나가지 않으며, Sync를 켜더라도 본인 GitHub 계정의 **비공개** Gist에만 저장됩니다.

## 시작하기

1. **이 저장소를 내려받습니다** (또는 `index.html`과 `history.html` 두 파일만 — 같은 폴더에 있어야 합니다).

   ```bash
   git clone https://github.com/<your-username>/custom_homepage.git
   ```

2. `index.html`의 **전체 로컬 경로**를 확인합니다. 예:

   ```
   /Users/yourname/Documents/GitHub/custom_homepage/index.html
   ```

3. **브라우저 홈페이지로 지정합니다.**

   ### Safari (macOS)
   - Safari 메뉴 → **설정(Settings)** → **일반(General)**
   - **홈페이지(Homepage)**에 `file://` 형식의 전체 경로를 입력, 예:
     ```
     file:///Users/yourname/Documents/GitHub/custom_homepage/index.html
     ```
   - **"새 윈도우/새 탭 열기"** 항목을 **홈페이지(Homepage)**로 설정.

   ### Chrome
   Chrome에는 "시작 페이지" 개념이 세 가지로 나뉘어 있고, 각각 별도로 설정해야 합니다.

   **A. 홈 버튼 페이지** (🏠 홈 아이콘을 눌렀을 때 이동하는 페이지)
   1. `chrome://settings/appearance` 로 이동합니다 (또는 **⋮ 메뉴 → 설정 → 모양**).
   2. **홈 버튼 표시**를 켭니다.
   3. **맞춤 웹 주소 입력**을 선택하고, 위 2단계에서 확인한 `file:///...` 전체 경로를 붙여넣습니다.
   4. 툴바에 홈 버튼이 안 보인다면 바로 이 토글을 켜면 주소창 옆에 아이콘이 나타납니다.

   **B. 시작 그룹 페이지** (Chrome을 켤 때 열리는 페이지)
   1. `chrome://settings/onStartup` 으로 이동합니다 (또는 **⋮ 메뉴 → 설정 → 시작 그룹**).
   2. **특정 페이지 또는 여러 페이지 열기**를 선택합니다.
   3. **새 페이지 추가**를 눌러 같은 `file:///...` 경로를 붙여넣고 **추가**를 클릭합니다.

   **C. 새 탭 페이지** (새 탭을 열거나 ⌘T를 눌렀을 때 보이는 페이지)
   Chrome은 기본 새 탭 페이지를 로컬 파일로 직접 바꾸는 것을 허용하지 않으므로, 항상 작은 확장 프로그램이 필요합니다.
   1. Chrome 웹 스토어에서 **[New Tab Redirect](https://chromewebstore.google.com/detail/new-tab-redirect/icpgjfneehieebagbmdbhnlpiopdcmna)** 를 설치합니다.
   2. `chrome://extensions` 로 이동해 **New Tab Redirect**를 찾고 **세부정보**를 클릭한 뒤 **파일 URL에 대한 액세스 허용**을 켭니다 (필수 — 이걸 켜지 않으면 확장 프로그램이 `file://` 페이지를 열 수 없습니다).

   
   <img width="977" height="1329" alt="image" src="https://github.com/user-attachments/assets/1438a82b-f568-40ad-a7f8-655cb765fbf1" />


   3. 확장 프로그램의 **옵션**을 엽니다 (또는 툴바 아이콘 우클릭 → **옵션**).
   4. **Redirect URL** 항목에 같은 `file:///...` 경로를 붙여넣고 저장합니다.


<img width="2522" height="1440" alt="image" src="https://github.com/user-attachments/assets/32d2dba7-b3ab-47c5-b9e6-b8d0549182c0" />

   
   5. 새 탭을 열어 홈페이지가 뜨는지 확인합니다.

   세 가지를 모두 설정할 필요는 없습니다 — 실제로 쓰는 진입 지점만 골라서 설정하면 됩니다 (대부분은 B와 C만 있으면 충분합니다).

4. 새 윈도우/탭을 열면 새 홈페이지가 보입니다. **+** 타일을 눌러 나만의 바로가기를 추가해 보세요.

## 기기 간 동기화

기본적으로 데이터는 `localStorage`에 저장되며, 이는 **브라우저별·기기별로 분리**됩니다 — `file://` 사본, 배포된 `https://` 사본, 그리고 두 번째 노트북은 모두 별개의 저장소라 서로 아무것도 공유하지 않습니다. 선택 기능인 **Sync**는 바로가기·할 일·테마를 모든 기기가 함께 읽고 쓰는 하나의 **비공개 GitHub Gist**에 저장해 이들을 연결해 줍니다.

> 히스토리는 각 기기의 방문 기록을 사적으로 유지하기 위해 **동기화하지 않습니다.**

### 1. GitHub 토큰 만들기 (최초 1회)

1. **[github.com/settings/tokens/new](https://github.com/settings/tokens/new?scopes=gist&description=Homepage%20sync)** 로 이동합니다 (Personal access tokens → **Tokens (classic)**).
   - 반드시 **classic** 토큰이어야 합니다 — fine-grained 토큰은 Gist API에서 **동작하지 않습니다.**
2. 이름을 지정하고(예: `Homepage sync`), **`gist`** 스코프 **하나만** 체크합니다. 다른 것은 체크하지 마세요.
3. 토큰을 생성하고 복사합니다 (`ghp_...` 형태).

### 2. 첫 번째 기기 설정

1. **Sync** 버튼(우측 상단, 원형 화살표 아이콘)을 클릭합니다.
2. **GitHub token** 칸에 토큰을 붙여넣습니다.
3. **Gist ID**는 비워 둡니다 (최초이므로).
4. **Push**를 클릭합니다. 새 비공개 Gist가 생성되고 **Gist ID** 칸이 자동으로 채워집니다 — 그 **Gist ID를 복사**해 두세요. 다른 기기에서 필요합니다.

### 3. 다른 기기 설정

1. 두 번째 기기에서 같은 홈페이지를 열고 **Sync**를 클릭합니다.
2. **같은 토큰**과 첫 기기에서 복사한 **Gist ID**를 붙여넣습니다.
3. **Pull**을 클릭해 바로가기·할 일·테마를 내려받습니다.

이것으로 끝입니다. 이후부터는:

- **자동 Push** — 바로가기·할 일·테마를 변경하면 페이지가 자동으로 Gist에 반영합니다(2초 디바운스). 다이얼로그를 열 필요 없습니다.
- **자동 Pull** — 페이지가 로드될 때마다 Gist에서 최신 데이터를 조용히 받아오므로, 다른 기기에서 변경한 내용을 자동으로 반영합니다.
- **수동 Push / Pull** — 강제로 동기화하고 싶으면 Sync 다이얼로그에서 언제든 사용할 수 있습니다.

토큰과 Gist ID는 해당 브라우저의 `localStorage`(`hp.sync.token`, `hp.sync.gistId`)에만 저장됩니다.

### ⚠️ 보안 주의사항

**토큰은 반드시 Sync 다이얼로그의 토큰 칸에만 붙여넣으세요** — 바로가기 이름/URL이나 할 일에 절대 넣지 마세요. 이 필드들은 Gist 내용으로 동기화되며, GitHub의 시크릿 스캐닝이 거기서 토큰을 발견하면(비공개 Gist라도) **자동으로 폐기(revoke)** 합니다. 그런 일이 생기면 새 토큰을 만들어 다시 Push하면 됩니다.

### 동기화 초기화

특정 기기가 예전 Gist ID에 물려 계속 옛 데이터를 가져온다면, 그 페이지에서 브라우저 개발자 콘솔을 열고 다음을 실행하세요:

```js
localStorage.removeItem('hp.sync.gistId');
localStorage.removeItem('hp.sync.token');
location.reload();
```

그런 다음 Sync 다이얼로그에서 올바른 토큰과 Gist ID를 다시 입력합니다.

## 참고 및 제약

- 로컬 `file://` 페이지로 열도록 설계되었습니다 — 서버가 필요 없고 오프라인에서도 계속 동작합니다(바로가기·할 일·히스토리 모두 동작하며, 파비콘 이미지와 검색 제안만 인터넷 연결이 필요합니다).
- 파비콘은 Google의 공개 파비콘 서비스에서 가져옵니다. 사이트에 캐시된 아이콘이 없거나 오프라인이면 자동으로 이니셜 색상 타일로 대체됩니다.
- 브라우저는 웹 페이지가 실제 방문 기록을 읽는 것을 허용하지 않습니다 — 여기의 **히스토리** 페이지는 *이 홈페이지에서 직접* 클릭한 것(바로가기, Google 앱, AI 링크, 입력한 주소)만 최대 50건까지 기록합니다.
- macOS Safari에 최적화되어 있지만 다른 최신 데스크톱 브라우저와 모바일에서도 동작합니다(반응형 레이아웃).
- 모든 데이터는 브라우저별·기기별로 분리된 `localStorage`에 저장되므로 그 자체로는 기기·브라우저 간에 동기화되지 않습니다 — 바로가기와 할 일을 여러 기기에서 공유하고 싶다면 [Sync](#기기-간-동기화)를 켜세요.
